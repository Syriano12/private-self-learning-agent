# Private Self-Learning Agent — Architecture

## الهدف

هذه النواة هي وكيل عام قابل للتوسعة، يعمل أساساً على Termux/Android، مع أقل قدر ممكن من الاعتماد على خصائص Termux. يعتمد الإصدار الأول على Python، وواجهة CLI، وواجهة FastAPI اختيارية، ولا يحتوي على واجهة رسومية أو تكامل WhatsApp.

## مبادئ التصميم

1. **Core مستقل عن المنصة:** منطق الوكيل لا يستدعي أوامر Termux مباشرة. أي تكامل خاص بالمنصة يمر عبر adapters قابلة للاستبدال.
2. **التعلم ليس سجلاً نصياً:** المعرفة لا تُعد مكتسبة إلا إذا رُبطت بمصادر وأدلة، ومرت بالتقييم، وأصبحت قابلة للاسترجاع والتطبيق.
3. **التخطيط ديناميكي:** المهمة تُحوّل إلى خطة بيانات قابلة للتعديل، وليس إلى Workflow خاص بالمثال الأول.
4. **الفصل بين التنفيذ والتحقق:** Executor ينفذ، بينما Verification Engine يقيّم الأدلة الناتجة باستقلال منطقي.
5. **الأمان افتراضيًا:** الأدوات تملك صلاحيات ومستويات خطر، والإجراءات الخارجية الحساسة تحتاج Approval Gate.
6. **توافق الموارد:** الإصدار الأول يستخدم SQLite وstdlib قدر الإمكان، لتقليل مشاكل الحزم الثنائية على Termux.

## طبقات النظام

```text
CLI / FastAPI
     |
Application Service
     |
Orchestrator: understand -> retrieve -> plan -> execute -> observe -> verify -> recover -> reflect
     |                         |                |
Memory & Knowledge       Tool Registry     Approval Gate
     |                         |
SQLite stores          Research / HTTP / Filesystem / Safe Python
```

|---|---|---|
| `Orchestrator` | إدارة دورة المهمة وإعادة التخطيط | نعم |
| `Planner` | تحويل الهدف إلى خطوات عامة مبنية على الأدوات المتاحة | نعم |
| `ToolRegistry` | اكتشاف الأدوات والتحقق من مخططاتها وصلاحياتها | نعم |
| `ResearchTool` | البحث واستخراج صفحات عامة مع حفظ الأدلة | نعم |
| `KnowledgeStore` | المعرفة الدلالية والإجرائية والثقة والتعارضات | نعم |
| `MemoryStore` | الذاكرة العرضية وسجل التجارب | نعم |
| `SkillRegistry` | إنشاء المهارات واختبارها وإصدارها وتعطيلها | نعم |

## دورة التعلم

```text
LEARN GOAL
 -> RESEARCH MULTIPLE SOURCES
 -> EXTRACT CLAIMS AND EVIDENCE
 -> IDENTIFY UNCERTAINTY/GAPS
 -> RUN SAFE EXPERIMENTS WHEN APPLICABLE
 -> EVALUATE
 -> CONSOLIDATE
 -> STORE KNOWLEDGE + EPISODE
 -> CREATE/UPDATE SKILL WHEN REUSABLE
 -> VERIFY FUTURE RETRIEVAL AND APPLICATION
```

## دورة التنفيذ

المحرك لا يعرف مسبقاً أن المهمة هي مقارنة مشاريع. يستقبل هدفاً نصياً، ويحلله إلى نية ومعايير، ثم يختار الأدوات من السجل. إذا فشلت أداة أو كانت الأدلة غير كافية، يسجل الملاحظة، يشخّص الفجوة، ويعدّل الخطة ضمن حد محاولات قابل للضبط.

## نموذج البيانات

يفصل التخزين بين:

- `tasks`: الهدف، الحالة، الخطة، المحاولات، checkpoints.
- `episodes`: ما حدث في مهمة سابقة، النتائج، الفشل، الدروس.
- `knowledge_items`: ادعاء أو إجراء موثق مع المصدر والدليل والثقة وحالة التحقق.
- `sources`: عنوان المصدر، النوع، الموثوقية، وقت الوصول.
- `skills`: مهارات قابلة للاختبار والإصدار، مع source knowledge وsuccess rate.
- `reflections`: تغيّر المعرفة، الفجوات، وإجراءات التحسين.

## حدود الإصدار الأول

يتضمن الإصدار الأول: بحث HTTP عام، استخراج نص أولي، تخزين SQLite، استرجاع بالكلمات المفتاحية، Orchestrator ديناميكي، تحقق من الأدلة والتغطية، تسجيل الفشل والتعافي، CLI، FastAPI، واختبار السلوك التعلمي عبر مهمتين منفصلتين.

يُؤجل إلى إصدارات لاحقة: WhatsApp، المتصفح التفاعلي، تنفيذ أوامر نظام عامة، تشغيل كود غير موثوق، البحث الأمني، التضمينات الدلالية الثقيلة، وmulti-agent orchestration.

## التشغيل

على Termux، يُفضّل تثبيت Python والحزم المتاحة من مدير حزم Termux عند الحاجة، ثم إنشاء بيئة افتراضية للمشروع. لا يعتمد المشروع على Docker أو systemd. يمكن تشغيل API محلياً على `127.0.0.1`، ويمكن نقل الكود إلى Linux/VPS مع تغيير متغيرات البيئة فقط.
